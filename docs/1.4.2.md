# NeoTab 1.4.2

Local hotfix prepared from `v1.4.1`. This version has not been pushed, tagged or published.

## Fixes

- Malformed or missing `config.yml` and `regions.yml` now fail the reload while retaining the last valid configuration. Both files are parsed before a command reload changes runtime services. A file that failed validation is protected from subsequent persistent edits until it is repaired and successfully reloaded.
- Region profiles now respond to successful teleports, portals and world changes. Cancelled teleports and portals are ignored.
- Nearest-player searches cache positions once per pass, skip geometrically irrelevant visibility checks, and stop after a visible zero-distance match. Search work is limited to 4,096 candidate inspections and 64 completed viewers per tick; unfinished searches continue on subsequent ticks. Target visibility, connection, world and range are checked again before publication.
- Timers and stopwatches use an individual monotonic clock. Starting another session no longer borrows the phase of an existing scheduler task, server lag does not slow the measured duration, and pause/resume preserves fractional seconds. Display updates still follow the server scheduler.
- Queued chat answers and timeout callbacks are bound to their original input session. They cannot complete or cancel a replacement prompt.
- GUI click actions run on the next tick. Actions are discarded after the menu changes, a reload begins, the player disconnects or the plugin stops.

## Compatibility and validation

Java 21 and Minecraft 1.20.6+ remain the targets. Existing config keys, commands and permissions are preserved; no config migration is required. The new `storage-read-only` message is included in both English and German.

The Gradle build, platform compatibility check and 65 tests pass, including 14 new regression tests. The runtime smoke results are recorded separately in `docs/1.4.2-validation.md`. No visual client test was performed.

The search operation counts in the regression test are deterministic synthetic workload measurements, not a TPS/MSPT benchmark. For 1,000 visible players at the same coordinates, the full search uses 3,000 position reads and 2,000 visibility checks, compared with 1,001,000 and 999,000 respectively in 1.4.1. Dense groups without visible matches can still require quadratic total candidate work, but that work is bounded per tick.

## Recovery after a rejected reload

Repair the indicated YAML file and run `/tab reload` again. Until this succeeds, NeoTab continues displaying the last valid settings and rejects persistent edits to the protected file. At initial startup there is no previous in-memory configuration; an invalid file prevents a normal enable instead of silently replacing user data with defaults.
