# NeoData M1: repository audit (before implementation)

- The repository is a Java 21 Gradle project targeting the Spigot 1.20.6 API, with a shaded shared Paper/Spigot/CraftBukkit JAR and JUnit 5 tests. Version is 2.0.0-Beta.1.
- Existing uncommitted work: README, build version, ConfigManager, NeoTab lifecycle, TabCommand, TabUpdater, plugin.yml, TabRegionRegressionTest, the new BossBarService and 2.0.0-Beta.1 milestone. Preserve all of it.
- NeoTab.onEnable creates AsyncYamlWriter, ConfigManager and runtime services; onDisable stops tasks, restores owned tab fields and closes the writer. TabCommand reload gates commands, flushes pending writes, validates both YAML files, then restarts services. Bukkit tasks generally execute on the server thread; update checks are asynchronous.
- ConfigManager reads config.yml via NeoTab and YamlFileGuard, overlays packaged defaults and caches immutable snapshots. Mutations update the in-memory Bukkit configuration, serialize it and queue writes through AsyncYamlWriter. The writer serializes writes on one daemon thread, coalesces snapshots, uses a temporary file and atomic replacement when available, records failures and provides an asynchronous flush barrier.
- RegionManager loads regions.yml through its own guard, maintains region and spatial caches, and writes reconstructed YAML through the same writer. First-time regions file creation uses a bundled resource or synchronous save. NeoTab.saveDefaultConfig creates initial config.yml. ConfigManager loads messages.yml/messages_de.yml and writes newly added default message keys through the writer. bStats and update checker have their own external behavior; bStats owns its own files. No other application persistence writer was found in src/main Java.
- YamlFileGuard protects a failed config/regions reload from subsequent edits; an accepted candidate restores writability. Existing legacy YAML and unknown config keys must remain in place. RegionManager serializes its own model, whereas ConfigManager serializes its loaded configuration.
- Tests cover core regressions, ownership, storage failure, runtime services, GUI lifecycle, permissions, visibility and metrics. Build includes a platform compatibility verification task. Existing tests use JUnit and selected real temporary-file operations.
- NeoData must not introduce a second writer for config.yml or regions.yml. Cross-plugin service discovery cannot rely on duplicated plugin classes; a common server-loaded/JDK boundary or explicitly shared API must be used. Persistence integration must account for reload barriers, failed writes and lifecycle ordering.
- These two YAML paths must not be unified mechanically: ConfigManager serializes the loaded configuration, whereas RegionManager reconstructs a document from its region model. Reconstructing config.yml in the same way could discard unknown settings. M1 must preserve each path's existing semantics and account separately for unknown region fields before any region migration.
