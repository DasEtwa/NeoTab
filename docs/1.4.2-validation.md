# NeoTab 1.4.2 validation

Date: 2026-09-05.

The complete Java-21 Gradle build and platform compatibility check passed with 65 tests (51 existing + 14 hotfix regressions). The integrated 1.5.0 development snapshot passed its complete build and 105 tests.

Each run checked plugin enablement/version, reload, retained region listing, refusal to overwrite intentionally corrupted config and region files, repair followed by successful persistence, nearest-player toggles and clean shutdown. The intentionally rejected reloads log errors by design. No unexpected NeoTab enable/disable, scheduled-task or command exceptions were observed.

The provided Paper 26.2 development build (`26.2-10-dev`, API `26.2.build.10-alpha`) cannot initialize the supplied PlaceholderAPI 2.12.2 JAR: PlaceholderAPI itself throws `NumberFormatException` while parsing the server version. NeoTab continues with LuckPerms and without PlaceholderAPI. A separate Paper 1.21.11 run confirms that both integrations enable successfully with the final 1.4.2 JAR; the 1.5.0 snapshot also passes with both there. No third-party plugin or original server was modified.

The isolated smoke runs did not use a connected Minecraft client. After those runs, the maintainer confirmed that the manual visual test passed on Paper 1.21.11 with the final NeoTab 1.4.2 JAR and the existing server configuration. The individual manual scenarios were not separately recorded; this confirmation is not a large-player-count TPS/MSPT benchmark. GUI scheduling, visibility, timing and chat races are also covered through deterministic API-level regression tests.

All six runtime tests used JARs byte-identical to the final artifacts. Tests ran one server at a time in freshly created local-only server folders, and all started server processes exited. During the isolated smoke runs, original server directories were used only as sources for runtime copies. For the subsequent manual test, the existing Paper 1.21.11 server was upgraded to the same 1.4.2 JAR after backing up its prior JAR and NeoTab data folder; its config.yml was verified byte-identical to the backup at startup. The maintainer subsequently reported that this server was shut down.
