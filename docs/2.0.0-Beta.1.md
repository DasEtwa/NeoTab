# NeoTab 2.0.0-Beta.1 — development milestone

Status: local development; not published. The latest published version is 1.4.2, according to [Modrinth](https://modrinth.com/plugin/neotab/versions).

## Tab field ownership recovery

Addresses [issue #4](https://github.com/DasEtwa/NeoTab/issues/4): NeoTab yields a player-list name, header, or footer when another plugin changes it, then can reclaim the field when it is cleared or restored to its value before NeoTab took control. The three fields are handled independently. A foreign value that remains set is not overwritten.

The Bukkit API does not identify a field's owner. A cleared field is therefore treated as released, even if another plugin intentionally manages it as empty. A foreign value that remains set cannot be distinguished from an active owner and is not reclaimed.

## Validation

Automated regression coverage checks yielding, leaving a foreign value untouched, reclaiming cleared and restored values, and avoiding unnecessary writes. A live test with a second plugin and a connected player is still pending.

## Global BossBars

Named BossBars can be created, edited, colored, enabled, disabled, removed, and listed with `/neotab bossbar` or `/neotab bb`. Titles support MiniMessage colors. An optional repeating schedule specifies the interval between starts and the display duration; schedules use server ticks and restart when settings are changed or reloaded. Settings persist in `config.yml` and bars are shown to all online players, including later joins.

The full Gradle build passed. A local Paper 26.3 smoke test confirmed plugin startup, creation, color and schedule commands, listing, and clean shutdown. A connected-client visual and timed-display test is still pending.
